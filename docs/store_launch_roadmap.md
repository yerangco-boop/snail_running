## 플레이스토어 출시 로드맵 (2026-09-29 정리, **보류 — 지금 진행 안 함**)

배경: 공모전 금상 수상 후 "완성도를 높여 플레이스토어에 올려 수익화"를 목표로 세움. **사용자가 "지금 할 것 아니다, 필요할 때 참고"로
보류 결정** — 먼저 착수를 제안하지 말고, 사용자가 출시 작업을 꺼낼 때 이 목록부터 볼 것. (아래 수치·정책은 2026-09 기준이므로 착수 시 최신 정책 재확인)

### 출시 차단 요소 (심사 거절 사유)
- **패키지 ID**: 현재 `com.example.snail_running`(`android/app/build.gradle.kts`의 `namespace`/`applicationId`) — `com.example.*`는 업로드 불가.
  예: `kr.hongjungpyo.snailrunning`. **한 번 올리면 영구 변경 불가**라 신중히 결정. 바꾸면 기존 설치본과 별개 앱이 됨(데이터 이전 안 됨)
- **v36 자체 업데이트 알림**(`update_checker.dart`, GitHub APK 다운로드 유도): 스토어 배포 앱이 스토어 밖에서 업데이트하는 건 정책 위반 → 스토어 빌드에선 비활성화(빌드 플래그 등)
- **`ACCESS_BACKGROUND_LOCATION`**: 가장 까다로운 심사 항목(신고서 + 시연 영상, 거절 잦음). 러닝은 사용자가 화면에서 직접 시작하므로
  **포그라운드 서비스(type=location) + "앱 사용 중" 권한만으로 화면 꺼짐 중 기록이 되는지** 실외 검증해볼 가치 큼 — 되면 이 권한 제거.
  단 v18 거리 유실 해결이 always 권한과 함께 이뤄졌으므로 제거 시 반드시 실측으로 회귀 확인. 포그라운드 서비스 유형 신고는 어느 쪽이든 필요
- **지도 타일**: OSM 공용 서버는 소규모 전제 → MapTiler/Stadia 등 키 기반 무료 티어로 이전(키는 `--dart-define`)
- **OpenWeatherMap 키**: `--dart-define`이라도 APK에서 추출 가능 + 무료 호출 한도 있음 → 사용자 수 늘면 프록시 서버나 호출 캐싱 검토
- **개인정보처리방침 URL** 필수(위치 데이터 사용) — GitHub Pages에 한 페이지로 게시 가능. Play Console "데이터 보안" 설문도 작성
- **AAB 빌드**: 스토어는 `.aab` 요구 → `release-apk.yml`에 `flutter build appbundle` 추가. 서명은 기존 키스토어를 업로드 키로 쓰고 Play App Signing 사용
- **targetSdk**: 매년 8월경 요구 수준 상향 — 착수 시 `flutter.targetSdkVersion` 값이 요구치 충족하는지 확인

### 계정·일정
- 구글 개발자 계정 등록비 25달러(1회)
- 신규 개인 계정은 **테스터 12명 × 14일 비공개 테스트** 통과 후 정식 출시 가능 — 학과 학생들에게 부탁하는 안
- 유료 판매/인앱 결제 시 결제 프로필·사업자 정보 필요

### 수익 모델 (논의한 방향)
- 일반 러닝앱 시장은 나이키런·스트라바·가민이 무료로 선점 → **"슬로우 조깅 전용"이 차별점**
- 러닝 중 광고는 사용 경험을 해침. 광고를 넣는다면 운동 종료 후 요약 화면 정도로 한정
- 추천: **기본 무료 + 프리미엄 1회 구매**(랩 분석, 보폭·케이던스 추이 그래프, 테마 등). 초기엔 구독보다 거부감이 적음
- 슬로우 조깅의 발상지는 일본 → **일본어 현지화**가 수익 면에서 효과가 클 수 있음
- 초기 수익은 크지 않을 가능성이 높다는 점은 사용자와 공유함. "수상작 + 스토어 출시 + 실사용자" 이력 자체도 가치가 있음

### 완성도 항목
활동 종류 선택(위 작업 목록의 보류 항목), 첫 실행 권한 안내 온보딩, 기록 백업/내보내기, 스토어 스크린샷·소개 문구

### 제안했던 착수 순서
①패키지 ID 결정 → ②스토어 빌드 설정(업데이트 알림 끄기, AAB, 타일 키) → ③백그라운드 위치 권한 없이 실외 검증 → ④개인정보처리방침 → ⑤비공개 테스트
